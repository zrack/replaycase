# ReplayCase v0.5.0-rc.1

**Status: unpublished local preview candidate for v0.5.0.** The current published
operator package remains [v0.4.0](v0.4.0.md). These notes do not establish a
published tag or a completed field handoff.

This candidate adds portable multi-bundle investigations. A case retains the
original incident bundles, cited findings and open questions, and comparisons
that another installation can reproduce. Existing capture, replay, incident
export, and evidence-receiver workflows remain available.

## Local validation

The complete `npm run check` gate passed on macOS with Node.js `26.12.1` and
npm `11.20.0`: TypeScript, 329 unit/integration tests, production app and CLI
builds, CLI smoke checks, 61 source-browser tests, and all 9 unpacked-package
tests. The browser gates ran Chromium, Firefox, and WebKit. Two planned source
skips run the standalone maximum-tier import-cancellation check only in
Chromium; the complete 200,000-record workflow passed in every engine.

Two independent builds produced identical package, manifest, SBOM, and checksum
bytes. All three asset checksums and every manifested payload hash were verified;
the package whitelist and CycloneDX references passed inspection. Stable and
prerelease publication arguments were also checked locally without publishing.

This is a dirty, untagged preview build. Its manifest identifies the base HEAD
commit and explicitly records uncommitted source changes. The local
`output/release/readiness.json` report and `candidate-source.patch` preserve the
validation record and source delta. Publication still requires the reviewed
merge, clean-main recheck, annotated tag, and pinned-toolchain release workflow
described in [the maintainer process](../../CONTRIBUTING.md#maintainer-release-process).

## Evaluate the local candidate

Requires Node.js 20.19 or newer and a local browser. Use the four candidate
assets built together in `output/release/`:

- `replaycase-0.5.0-rc.1.tgz`
- `replaycase-0.5.0-rc.1.release.json`
- `replaycase-0.5.0-rc.1.cdx.json`
- `SHA256SUMS`

From that directory on macOS, verify the checksums and unpack into a new local
directory without replacing an installed ReplayCase version:

```bash
shasum -a 256 -c SHA256SUMS
mkdir replaycase-0.5.0-rc.1-evaluation
tar -xzf replaycase-0.5.0-rc.1.tgz -C replaycase-0.5.0-rc.1-evaluation
node replaycase-0.5.0-rc.1-evaluation/package/bin/replaycase.mjs version --json
node replaycase-0.5.0-rc.1-evaluation/package/bin/replaycase.mjs serve --app-port 47891 --bridge-port 0
```

On GNU/Linux, use `sha256sum -c SHA256SUMS`. Compare the reported version
`0.5.0-rc.1` and full commit with the external manifest before collecting
evidence. Inspect the manifest's `mode`, `dirty`, `tagVerified`, and
`tagAnnotated` fields as well. An untagged local build is a `preview`; its
`tag` names the expected tag and does not prove that tag exists. A dirty build
contains worktree changes beyond its recorded HEAD commit.

The server opens `http://127.0.0.1:47891/` and manages its authenticated bridge.
Stop it with `Ctrl+C`. This evaluation port selects separate browser storage
from the stable default `http://127.0.0.1:47890/`; an empty library at the new
origin does not mean the stable library was removed. Export any cases or
sessions needed elsewhere. Keep the original downloaded evidence files.

## Multi-bundle cases

Choose **Cases**, create a title, and **Add bundles** containing the baseline,
failure, and post-fix `.nlb` evidence. Exact duplicate bundle bytes share one
artifact. Add findings or questions with citations to an exact included range,
raw record, or diagnostic. Compare two included bundles with explicit alignment
and retain the result in the case.

**Save case** succeeds only after the local storage transaction commits.
**Export case** creates an `.nlcase` containing the original bundle bytes and
applied authored context. On another compatible installation, **Import case**
reverifies every nested bundle, resolves citations, and independently reproduces
saved comparisons before showing the case. Cancellation and rejected imports
preserve the active investigation; conflicting saved revisions are not merged.

Cases accept up to 16 distinct bundles, 48 MiB of stored bundle bytes, 64 MiB of
aggregate expanded nested artifacts, and a 1 MiB manifest inside a 64 MiB outer
archive. They support up to 200 findings/questions and 16 comparisons, subject
to the manifest limit. Review all embedded telemetry and authored context before
sharing. Case storage is local, origin-scoped, and unencrypted.

Use the [case procedure](../../USER_GUIDE.md#investigate-a-multi-bundle-case)
for detailed controls and recovery.

## Other changes

Diagnostic timeline controls expose their visible titles, grouped counts, and
timestamps in accessible names. Browser regression checks now distinguish the
completed case-save notice from progress messages and wait for the save focus
handoff before entering notes. Source-map-js, Vite, and Vitest/mocker updates
include upstream hardening fixes. The [changelog](../../CHANGELOG.md#unreleased)
owns the complete change record.

## Compatibility and remaining boundaries

Session versions 1 and 2 and bundle versions 3 and 4 remain readable. New
bundles remain version 4. Existing evidence extensions, format identifiers,
decoder-pack identities and hashes, parser runtimes, browser storage keys, and
the `narrowslink` CLI alias remain unchanged. A v0.4.0 receiver can inspect the
individual `.nlb` bundles but does not support `.nlcase`; use a case-capable
installation for the complete investigation.

The CLI command `replaycase verify incident.nlb --json` verifies `.nlb`, not
`.nlcase`. Cases are verified through **Import case** in the application.
Offline browser inspection needs the running local application server; it has
no external-service dependency and no serverless browser-cache mode.

Citations resolve evidence locations without establishing narrative truth.
Cases preserve separate session clocks and do not infer synchronization or
causality. Internal consistency, evidence completeness, and source authenticity
remain separate claims. Candidate checksums, bundles, and cases are unsigned.
Matching hashes do not authenticate the publisher, source system, or operator.

Physical Web Serial hardware, native device permission behavior, manual
assistive-technology certification, and a real-source second-person field
handoff remain separate from automated browser-engine coverage. No completion
of those activities is claimed by this candidate.
