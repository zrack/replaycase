# Code of Conduct

ReplayCase is built for careful investigation. We expect the same care in project collaboration.

## Expected conduct

- Discuss ideas, code, and evidence without attacking the person presenting them.
- Make technical claims reviewable: state assumptions, share reproducible steps, and correct mistakes openly.
- Welcome questions and differing levels of experience. Explain project-specific language when it helps others participate.
- Protect people and operators. Never post secrets, personal data, operational telemetry, precise locations, device identifiers, or other sensitive evidence.
- Respect boundaries, licenses, attribution, and a contributor’s decision to disengage.

Harassment, threats, discriminatory language, sexualized attention, deliberate exposure of private information, and sustained disruptive behavior are not acceptable in project spaces.

## Reporting and response

For ordinary project concerns, contact the repository owner privately through their GitHub profile. Report security vulnerabilities by following [SECURITY.md](SECURITY.md), not in a public issue.

Maintainers may edit or remove content, limit participation, or ban contributors when needed to protect the project and its community. Reports will be evaluated on their evidence and impact, with information shared only as needed to resolve the concern. Good-faith reporters will not face retaliation.

This code applies to repository discussions, issues, pull requests, reviews, and other spaces represented as part of ReplayCase.
